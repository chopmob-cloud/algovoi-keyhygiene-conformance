# algovoi-keyhygiene-conformance

[![12-way consensus](https://github.com/chopmob-cloud/algovoi-keyhygiene-conformance/actions/workflows/consensus.yml/badge.svg)](https://github.com/chopmob-cloud/algovoi-keyhygiene-conformance/actions/workflows/consensus.yml)

A signed, cross-language conformance battery for **RSA/EC public-key hygiene and
primality soundness**. Given a candidate integer or a public key, every
independent implementation must reproduce the same accept/reject verdict,
byte-for-byte, including the adversarial cases that fool naive checks.

This is the **L0** layer of the AlgoVoi assurance stack: is the key material
sound *before* you sign with it?

```
L0  key soundness      is the prime / key sound at all        <- this repo
L1  canonicalisation   RFC 8785 (JCS) canonical bytes         (algovoi-jcs-conformance-vectors)
L2  signature verdict  RFC 9421 accept/reject over bytes      (algovoi-rfc9421-conformance)
```

## Why this exists

Rejecting weak keys is not a nicety, it is a compliance obligation. The
CA/Browser Forum Baseline Requirements require CAs to reject ROCA, Debian-weak,
and small-factor keys; eIDAS qualified trust service providers must validate key
material; HSM/TPM and government-PKI operators need third-party assurance that
their acceptance logic actually rejects the known-weak classes. None of them has
a neutral, signed, cross-language corpus to test against. This is that corpus.

It is deliberately **not** payment-specific: the primitives (primality, RSA
modulus hygiene) sit under every PKI, so the battery reaches the RSA-dominant
regulated industries (CAs, eIDAS, HSM/TPM, government identity, TLS/PKI audit).

## The sections

| Section | Each case | Verdict |
|---|---|---|
| `primality` | a candidate integer (decimal string) | prime? (Baillie-PSW ground truth) |
| `rsa_modulus_hygiene` | an RSA public key `(n, e)` | accept / reject + reason, under the CA/Browser-Forum-tracking policy |
| `batch_common_factor` | a **set** of RSA moduli | per key: shares a prime with another key? (batch-GCD) |
| `ec_key_hygiene` | an affine EC point `(curve, x, y)` | on-curve + in-range? (P-256, P-384, secp256k1) |
| `roca_fingerprint` | an RSA modulus `n` | carries the Infineon ROCA fingerprint? (CVE-2017-15361) |

`primality` carries the adversarial core: composites that are **strong
pseudoprimes** to a target base set, so a checker using Miller-Rabin over those
bases calls them prime. Every composite carries a factorisation, so the corpus
proves its own compositeness by multiplication, without trusting any primality
test.

`rsa_modulus_hygiene` rejects perfect-power moduli, small-factor moduli,
close-prime (Fermat-factorable) moduli, disallowed bit lengths, and disallowed
public exponents; it accepts valid 2048/3072/4096-bit moduli.

`batch_common_factor` models the Mining-your-Ps-and-Qs failure: some keys in the
set share a prime, so anyone holding the set factors them by a GCD. Shared keys
carry the shared prime, so the corpus proves the co-factor independently.

`ec_key_hygiene` validates EC public points: coordinates in `[0, p)` and on the
curve `y² ≡ x³ + ax + b (mod p)`. These curves have cofactor 1, so on-curve plus
in-range is sufficient (there is no small-order subgroup to screen, unlike the
cofactor-8 Edwards keygate in the sibling RFC 9421 battery).

`roca_fingerprint` detects the Infineon RSALib flaw (ROCA, CVE-2017-15361) that
broke Estonian eID, TPMs, and YubiKeys. Infineon primes have the form
`p = k·M + (65537^a mod M)`, so `n = p·q ≡ 65537^(a+b) (mod M)` and `n mod pf`
lies in the subgroup generated by 65537 for every prime `pf | M`. A random
modulus meets all of those subgroups only with negligible probability, so
"`n mod pf` is a power of 65537 for every `pf`" is the Bleichenbacher
fingerprint, detected library-free. The generator and prime set ship in the
corpus `policy`, so runners read them rather than hardcoding.

## The differential has teeth

```
python tools/demo_naive_divergence.py
```

demonstrates that each adversarial vector fools a naive fixed-base Miller-Rabin
checker while Baillie-PSW (ground truth) catches every one. A conformance corpus
of verdicts is only meaningful if a weak implementation actually gets some wrong;
this shows the primality section discriminates.

## Assurance

- **Signed corpus.** The corpus head (per-section digests + file hash) is
  canonicalised (RFC 8785 JCS) and EdDSA-signed via
  `algovoi-corpus-cm` (private); only
  the public JWK ships, the signing seed is a genuine secret held off-repo.
- **KAT gate** (`tools/check_kat.py`): verifies the head signature, and
  independently re-derives every verdict, composites by re-multiplying their
  factors, primes by deterministic Miller-Rabin sound in range, RSA reasons by an
  independent structural check, so a systematic error shared by the generator and
  a runner cannot pass as consensus.
- **12-way consensus**: twelve independent implementations, each using its own
  big-integer stack, reproduce every verdict byte-for-byte
  (`tools/run_consensus.sh --require 12`, fail-closed).
- **Hermetic cells**: each runner is re-run against the signed corpus inside a
  pinned Docker image (`kaf/run_cells.sh`), so the verdict holds in a clean,
  independent runtime.
- **Sealed receipt**: `kaf/seal_receipt.py` binds agreement + cells + corpus
  into one EdDSA-signed, re-verifiable receipt (`kaf/kaf_verify.py`); the seal
  secret is held off-repo, only the public JWK ships.
- **Mutation-proven teeth**: flipping any expected verdict makes every runner
  (and every cell) go red, so the runners genuinely compute rather than echo.

## Cross-implementation validation

Every case is reproduced byte-for-byte by twelve independent implementations,
each with its own big-integer stack and its own from-scratch Baillie-PSW (never a
stdlib primality shortcut):

| Language | Big-int stack | Language | Big-int stack |
|---|---|---|---|
| Python | `int` | Java | `BigInteger` |
| TypeScript | `BigInt` | Kotlin | `BigInteger` |
| Go | `math/big` | Scala | `BigInt` |
| Rust | `num-bigint` | .NET | `BigInteger` |
| C | GMP | Ruby | `Integer` |
| Elixir | native | PHP | GMP |

Latest sealed run: **59 cases across five sections, full 12-way consensus, 12/12
hermetic cells PASS** (`kaf/receipts/keyhygiene_v0.seq4.receipt.json`).

## Comparison with the sibling conformance corpora

This battery is the **L0** floor of a three-layer assurance stack; each layer is a
signed, cross-language, N-way conformance corpus sealed the same way (KAF:
Agreement · KAT · Cells · Seal).

| | keyhygiene (L0, this repo) | [jcs-conformance-vectors](https://github.com/chopmob-cloud/algovoi-jcs-conformance-vectors) (L1) | [rfc9421-conformance](https://github.com/chopmob-cloud/algovoi-rfc9421-conformance) (L2) |
|---|---|---|---|
| Question | is the key / prime sound? | are the canonical bytes right? | is the signature verdict right? |
| Standard | RSA/EC key hygiene + primality | RFC 8785 (JCS) canonicalisation | RFC 9421 (+ RFC 9530) HTTP signatures |
| Each case | integer / public key → verdict | JSON value → canonical bytes/hash | signing-base + key → accept/reject |
| Adversarial focus | strong pseudoprimes, ROCA, batch-GCD, close primes, off-curve points | Unicode / number-form / duplicate-key hazards | malleability, small-order keys, ECDSA range/off-curve |
| Independent implementations | **12 languages** | 10 languages | 12 languages |
| Assurance axes (KAF) | Agreement · KAT · Cells · Seal | Agreement · Strata · Cells · Seal | Agreement · KAT · Cells · Seal |

Together the three read **is the key sound → canonicalise → sign → verify** end to
end. Where L1/L2 are payment-adjacent, L0 sits under every PKI, so it reaches the
RSA-dominant regulated industries directly.

## Security scope (defensive only)

This is audit / key-acceptance conformance tooling. It ships **public keys and
crafted composites only, never private keys**. The weak keys exist to test
detection (ROCA and batch-GCD detection are published defensive techniques). It
contains no factoring engine aimed at live keys; bounded Fermat is used only as a
detector on the corpus's own crafted moduli.

## Run

```
python tools/gen_keyhygiene_v0.py                      # regenerate the corpus (deterministic)
python runners/python/verify_py.py                     # reference runner: reproduce every verdict
ALGOVOI_LOCAL_SRC=/path/to/algovoi-corpus-cm/src \
  python tools/sign_keyhygiene_v0.py                   # sign the head (off-repo secret)
ALGOVOI_LOCAL_SRC=/path/to/algovoi-corpus-cm/src \
  python tools/check_kat.py                            # fail-closed KAT gate
bash tools/run_consensus.sh --require 12               # twelve-way byte-for-byte consensus
bash kaf/run_cells.sh                                  # hermetic per-language Docker cells
python kaf/kaf_verify.py kaf/receipts/keyhygiene_v0.seq4.receipt.json  # verify the sealed receipt
```

Individual runners live under `runners/<lang>/` and each exits 0 iff every case
matches. Point `ALGOVOI_KEYHYGIENE` at a corpus to run any runner or gate
against it.
